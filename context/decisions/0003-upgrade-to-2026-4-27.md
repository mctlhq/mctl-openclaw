# ADR-0003: Upgrade openclaw from 2026.3.14 to 2026.4.27

- Status: accepted
- Date: 2026-04-30
- Deciders: platform engineering, on-call

## Context

All three mctl-openclaw tenants (admins, labs, ovk) were running
openclaw 2026.3.14. Six HIGH-severity CVEs disclosed between March 22
and April 27, 2026 were unpatched in that release:

| CVE            | CVSS | Fixed in   |
|----------------|------|------------|
| CVE-2026-41353 | 8.1  | 2026.3.22  |
| CVE-2026-41371 | 8.5  | 2026.3.28  |
| CVE-2026-41349 | 8.7  | 2026.3.28  |
| CVE-2026-41342 | HIGH | 2026.3.28  |
| CVE-2026-41359 | HIGH | 2026.3.28  |
| CVE-2026-41352 | 8.8  | 2026.3.31  |

In addition, 2026.4.26 removes a bearer-token echo vulnerability in
`device.token.rotate`, and 2026.4.27 delivers Telegram and Slack
reliability fixes relevant to the production ovk tenant.

## Decision

Upgrade all three tenants to openclaw 2026.4.27 using the mandatory
labs -> admins -> ovk promotion sequence (ADR-0001) with a 24-hour soak
between each promotion. The s3-sync canary CronWorkflow is stopped
before each rollout and restarted with the post-rollout delay per
ADR-0002.

Target chosen as 2026.4.27 (latest stable at time of upgrade) rather
than 2026.3.31 (last version that closes all CVEs) to also land the
bearer-token echo fix and Telegram/Slack reliability improvements in a
single upgrade cycle.

## Alternatives rejected

**A. Cherry-pick CVE patches onto 2026.3.14** — Rejected. Upstream does
not backport. Maintaining a long-lived fork branch for six CVEs across
five patch versions is not viable.

**B. Upgrade only to 2026.3.31** — Rejected. Defers 2026.4.26
bearer-token fix and 2026.4.27 Telegram/Slack improvements, requiring a
second upgrade cycle with identical canary/probe overhead and no
security benefit.

**C. Upgrade all tenants simultaneously** — Rejected per ADR-0001. Labs
must serve as a canary for ovk; simultaneous rollout removes that
protection.

## Consequences

- All six CVEs are remediated across all three tenants.
- Bearer-token echo is eliminated from `device.token.rotate` responses
  (2026.4.26). Any internal tooling that parsed the echoed token must be
  updated before the ovk rollout.
- Telegram and Slack reliability improves in ovk (2026.4.27 fixes).
- Manifest-first plugin startup (2026.4.27) is backward compatible;
  no YAML skill edits required.
- OpenTelemetry coverage expansion may add ~5-15 MB steady-state heap;
  monitored during labs soak (abort criterion: >50 MB above baseline).
- QQBot and Tencent Yuanbao channels (2026.4.27) are opt-in via config
  and are NOT enabled on any tenant without an explicit config change.
